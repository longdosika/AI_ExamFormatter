# กฎการ Capture รูปและตาราง (Capture Rules)

เอกสารนี้เป็นกฎกลางของการครอบรูป ตาราง และกราฟจากต้นฉบับ รวมถึงการล้างข้อความที่ซ้ำกับรูป ทุกคนที่แก้ระบบ capture ต้องอ่านก่อนแก้ และต้องเพิ่มแถวใน "บันทึกการเรียนรู้" ท้ายไฟล์ทุกครั้งที่แก้ (ดูขั้นตอนท้ายเอกสาร)

- **แม่แบบหลัก (คัมภีร์สูงสุด):** QuizFlow Import Template v1.1 สำเนาอยู่ที่ `evidence/t109-master-template.docx` ใช้กำหนดลำดับและขนาดรูปในผลลัพธ์
- **โค้ดหลัก:**
  - `lib/capture-geometry.ts`: ขอบเขตและหลักฐานตาราง
  - `lib/diagram-client.ts`: ครอบรูป
  - `lib/table-bounds.ts`: ตรวจเส้นตาราง
  - `lib/figure-text-cleanup.ts`: ล้างข้อความซ้ำในแบบร่าง
  - `lib/harvest-editor.ts`: นำรูปเข้าแบบร่างและจัดลำดับ
- **หน่วยพิกัด:** กรอบทุกกรอบเป็น `[บน, ซ้าย, ล่าง, ขวา]` สเกล 0–1000 ของหน้า

| C-02 | ห้ามใช้ข้อความ OCR ที่บันทึกไว้ซ้ำ ถ้าไม่มีตำแหน่งบรรทัดมาด้วย | T-125 |

|---|---|---|

| C-21 | ข้อความตารางลบได้เมื่อมีหลักฐานว่าเป็นตาราง (`hasCellRowEvidence` หรือ `hasTabularTextEvidence`) ให้ลบทั้งบรรทัด หรือชุดบรรทัดต่อเนื่องตั้งแต่ 2 แถวขึ้นไป | T-121 I-039: ห้ามตัดกลางคำ เช่น "สาร\|ประกอบ" |
| C-22 | ป้ายในรูป (ยาวไม่เกิน 15 ตัวอักษร) ลบได้เฉพาะเมื่ออยู่ท้ายโจทย์ เผื่อขอบ 2% | T-121 I-040: ข้อ 8 "D สี C สี B สี A สาร ก" |
| C-23 | ห้ามลบคำเดี่ยวกลางประโยค แม้จะตรงกับข้อความในรูป เช่น "เอทานอล" ที่อยู่ทั้งในตารางและในโจทย์ | T-124 |
| C-24 | ถ้าจับรูปไม่ได้ ให้คงแถวตารางไว้เป็นบรรทัดละแถว พร้อมป้าย [รูปต้องตรวจสอบ] ห้ามต่อเป็นประโยคเดียว | T-121 B-18 |
| C-25 | โจทย์หลายบรรทัดใน DOM เป็น `<br>` จึงต้องเทียบข้อความแบบไม่มีขึ้นบรรทัด และลบทั้งบรรทัด | T-121 I-039 |

## ง. การนำรูปเข้าแบบร่างและลำดับ

| รหัส | กฎ | กรณีจริง |
|---|---|---|
| C-30 | ลำดับต่อข้อตามแม่แบบหลักคือ โจทย์ → รูปคำถาม → ตัวเลือก → คำอธิบาย ทั้งในจอแก้ไขและ DOCX | T-121 I-037 |
| C-31 | ตัวเลือกที่เป็นรูปล้วน ถ้ายังไม่มีแถวตัวเลือก ให้สร้างแถวใหม่ (ใช้ส่วน "ตัวเลือก:" เดิมถ้ามี) | T-121 I-041 ชุด 1 ข้อ 16 |
| C-32 | รูปจาก detector มีสถานะ UNVERIFIED เสมอ ไม่ขึ้น CLEAN เอง | T-121 B-16 |
| C-33 | รูปที่ครอบด้วยระบบปัจจุบันมี `data-crop-version="2"` ส่วนรูปที่ผู้ใช้จับเองเป็น `manual` และห้ามเปลี่ยนอัตโนมัติ | T-124 |
| C-34 | แบบร่างเก่า: ล้างข้อความซ้ำให้ตอนเปิด ส่วนรูปเก่าตัดใหม่จากต้นฉบับเมื่อผู้ใช้กด "ตัดใหม่จากต้นฉบับ" เท่านั้น | T-124 |
| C-35 | รูปขนาดไม่เกิน IMAGE_MAX ของแม่แบบ (โจทย์/โจทย์ร่วม 661px, ตัวเลือก 353px, คำอธิบาย 510px) และคงสัดส่วน | T-109 |
| C-36 | ตารางที่เป็นตัวเลือก (หัวคอลัมน์ + แถว ก-ง ที่แปลงเป็นข้อความตัวเลือก "หัว: ค่า; หัว: ค่า" แล้ว) ไม่ใช่รูปโจทย์ ห้ามแนบเป็นรูปโจทย์ หลักฐาน: ข้อนั้นมีตัวเลือกจากตาราง ≥3 ข้อ และบรรทัด OCR ในกรอบมีหัวคอลัมน์อย่างน้อยครึ่ง และ (ค่าในช่อง ≥1/3 หรือหัวครบ + มีบรรทัดมากกว่าจำนวนตัวเลือก); ถ้าไม่มีบรรทัด OCR ในกรอบ ใช้คำอธิบายจาก AI ว่า "ตารางตัวเลือก" เท่านั้น แบบร่างเก่าที่มีรูปแบบนี้ถูกเอาออกตอนเปิด (isChoiceTableFigure) | T-130 |
| C-37 | ข้อหนึ่งมีรูปโจทย์ได้หลายรูป ห้ามรูปหลังทับรูปก่อน เก็บทุกรูปเรียงตามตำแหน่งในต้นฉบับ (บนลงล่างทีละแถว ซ้ายไปขวาในแถวเดียวกัน; สองกรอบอยู่แถวเดียวกันเมื่อซ้อนกันแนวตั้ง ≥ ครึ่งของกรอบที่เตี้ยกว่า) ในจอแก้ไขเป็นบล็อก "รูปโจทย์:" เดียว หนึ่งกรอบต่อรูป ส่งออกเป็น "รูปคำถาม:" หนึ่งป้ายตามด้วยรูปละหนึ่งย่อหน้า; สกัดซ้ำแทนที่รูปที่สกัดไว้ (ไม่ต่อท้ายซ้ำ) รูปที่ผู้ใช้จับเองคงไว้; C-36 ตัดเฉพาะรูปที่เป็นตารางตัวเลือก รูปอื่นของข้อเดียวกันอยู่ต่อ | T-131 I-059 ชุด 2 ข้อ 25 |

## ฉ. กฎ → โค้ด → test (ตรวจอัตโนมัติ)

- กฎไม่มีแถว หรือมีแถวแต่ไม่มีกฎ
- ไฟล์โค้ดไม่มีชื่อที่ระบุ (`ไฟล์#ชื่อ`)

   - ทดสอบทั้ง browser profile ใหม่ และ profile ที่มีแบบร่างเดิมของไฟล์นั้น (บทเรียน T-124/T-125)
2. **เขียน test ที่ fail ก่อนแก้**
   - unit: `scripts/test-diagram-contract.cjs`
   - browser replay: `scripts/test-t121-fidelity.cjs`, `test-t124-stale-draft.cjs`, `test-t125-cached-ocr.cjs`
3. **แก้โดยไม่ขัดกฎข้างบน** ถ้าต้องเปลี่ยนกฎ ให้แก้ตารางกฎพร้อมเหตุผล
4. **ตรวจผลด้วยตาเทียบต้นฉบับ** ดูรูปที่ครอบจริง ไม่ดูแค่ตัวเลข
5. **เพิ่มแถวใน "บันทึกการเรียนรู้" ด้านล่าง** และอัปเดต `release_log.md` (รหัส I-xxx)
6. **อัปเดตตาราง ฉ. (กฎ → โค้ด → test)** แล้วรัน `node scripts/test-capture-rules.cjs` ต้องผ่าน (อยู่ใน `npm test` และ completion gate อยู่แล้ว)
